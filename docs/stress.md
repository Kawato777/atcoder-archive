# ランダムテスト（愚直解と比べる）

サンプルは通るのに WA になるときや、境界（N=1、全部同じ値、端の要素など）が不安なときに使う。小さいランダムな入力をたくさん作り、**愚直解**（遅くても確実に正しい解。全探索や O(N²) のループ）と自分の解の出力を比べる。

使うファイルは 2 つ。どちらも **🎲 雛形を作る** で作れる。

| ファイル | 中身 | 書く人 |
| --- | --- | --- |
| `gen.py` | 入力を 1 つ作る Python。`python3 gen.py <seed>` で標準出力に出す | 雛形は `scripts/gen-init` が問題ページから正規表現で作る（生成 AI は使わない）。`# TODO` の部分を自分で直す |
| `brute.cpp` | 愚直解。中身は最初 `base.cpp` と同じ | **自分**（生成 AI は使わない） |

練習（`practice/`）と本番（`contest/`）で、ファイル名や見つかった入力の保存先、サンプルテストとの関係が違う。

| | 練習（`practice/ABC/485/C/main.cpp`） | 本番（`contest/ABC/485/C.cpp`） |
| --- | --- | --- |
| モード | 練習モード | 本番モード（ランダムテストはそのまま使える） |
| 入力生成器 | `practice/ABC/485/C/gen.py` | `contest/ABC/485/C.gen.py` |
| 愚直解 | `practice/ABC/485/C/brute.cpp` | `contest/ABC/485/C.brute.cpp` |
| 食い違った入力の保存先 | `practice/ABC/485/C/test/hack-000.in/.out` | `contest/ABC/485/C.hack/hack-000.in/.out` |
| 保存した入力は **▶ テスト実行** に入るか | **入る**（サンプルと同じ `test/` に置かれる） | **入らない**（本番は `test/` が無く、サンプルテスト自体が使えない） |
| コミットされるか | `gen.py`・`brute.cpp` はされる。`test/` は `.gitignore` 済みなので `hack-*` はされない | `C.gen.py`・`C.brute.cpp`・`C.hack/` もすべてされる（終了時点の状態として残す） |
| 終わったあと | ノートに落ちた入力を書く | 練習モードに戻してから振り返る。upsolve は `practice/` で取り直す |

---

## 練習（過去問）での使い方

1. **過去問を取得** で `practice/ABC/485/C/main.cpp` を作り、ふつうに解く
2. サンプルは通るのに WA になったら（または提出前に不安なら）、`main.cpp` を開いた状態で **テスト** 欄の **🎲 雛形を作る** を押す
   - `gen.py` と `brute.cpp` が作られ、右側に開く。すでにあるファイルは上書きしない
3. `brute.cpp` に愚直解を書く。**遅くてよいので確実に正しいもの**にする（全探索、すべての組を試す二重ループなど）
4. `gen.py` の `# TODO` を直す
   - 個数（N, H, W, 文字列の長さなど）は 8 以下、値は 0 に近い狭い範囲（ときどき制約の端）に縮めてある
   - 「相異なる」「グラフは単純」のような条件は読み取れないので、`# TODO` として先頭に残る。満たさない入力は `assert` で捨てられる（例: `assert len(set(C)) >= 2`）。捨てた seed は飛ばされる
   - 形式を読めなかった問題では例のままになるので、入力の形式どおりに `print` を書く
5. **▶ ランダムテスト** を押す。10 秒か 1000 件のどちらかに達するまで、seed を変えて比べ続ける
   - **全部一致**: 「N 件すべて一致」と出る。考え方は合っている可能性が高い（小さい入力の話なので、TLE やオーバーフローは別に考える）
   - **食い違った**: そこで止まり、「入力 / 愚直解の出力 / あなたの出力」が出る。入力は `test/hack-000.in`、愚直解の出力は `.out` に保存される
6. 表示された小さい入力で `main.cpp` を直す。`dbg(...)` を入れて **▶ テスト実行** を押すと、保存された `hack-000` もサンプルと一緒に流れるので、直ったかすぐ分かる
7. 直ったらもう一度 **▶ ランダムテスト** を押し、全部一致するまで 5〜6 を繰り返す
8. AC したら、ノートに「どんな入力で落ちたか」を書く（`hack-*.in` はコミットされないので、ノートに貼っておく）

### 愚直解なしで使う（▶ クラッシュ/TLE 検出）

愚直解がすぐ書けないときは、`gen.py` だけで **RE / TLE だけ** を調べられる。**▶ クラッシュ/TLE 検出** を押す（`brute.cpp` は不要）。

- 見つかるもの: クラッシュ、`vector` の範囲外アクセス（`-D_GLIBCXX_DEBUG`）、Linux ではサニタイザの検出、2 秒を超える実行（TLE）
- **見つからないもの: WA（答えの間違い）**。全部通っても「RE / TLE は無かった」だけで、答えが正しい保証はない。結果にも「WA は調べていません」と出る
- 見つかった入力は `hack-000.in` だけ保存される（比べる相手がいないので `.out` は作られない）。練習では **▶ テスト実行** に入り、期待する出力なしで実行される
- TLE を見るには `gen.py` 先頭の `SIZE_MAX` を大きくして、最大サイズの入力を作らせる
- **▶ ランダムテスト** は今まで通り `brute.cpp` が必要（無いとエラーになる）

### 愚直解が TLE / RE になったとき

「愚直解が TLE（無限ループ？）になりました」と出たら `brute.cpp` か `gen.py` を見直す。入力が大きすぎるなら、`gen.py` 先頭の `SIZE_MAX` を小さくするか、値の範囲を狭める。

## 本番（コンテスト中）での使い方

本番は時間との勝負なので、**使うのは「WA が出て、愚直解がすぐ書ける」とき** に絞る。目安は C・D で、全探索が 5 分以内に書ける問題。

1. **コンテスト用に作成** で `contest/ABC/485/A.cpp`〜 を作る（自動で本番モードになる）
2. C を提出して WA が出たら、`C.cpp` を開いた状態で **🎲 雛形を作る** を押す
   - `C.gen.py` と `C.brute.cpp` が同じフォルダに作られる
   - 雛形は問題ページを読んで作る。読めなかった場合は例のまま作られるので、入力形式どおりに手で書く
3. `C.brute.cpp` に愚直解を書き、`C.gen.py` の `# TODO` を直す。**どちらも自分で書く**（本番中は Claude の機能は止まっている）
4. **▶ ランダムテスト** を押す
   - 食い違った入力は `C.hack/hack-000.in/.out` に保存され、画面に「入力 / 愚直解の出力 / あなたの出力」が出る
5. 直したあとの確かめ方が練習と違う。本番では **▶ テスト実行** で `C.hack/` は流れないので、次のどちらかで確かめる
   - もう一度 **▶ ランダムテスト** を押す（seed は毎回 1 から順に試すので、同じ入力も最初にもう一度試される）
   - `C.hack/hack-000.in` の中身を `contest/ABC/485/input.txt` にコピーし、**input.txt で実行** を押して、`hack-000.out` と見比べる
6. 全部一致したら提出する

### 本番で気をつけること

- **時間をかけすぎない**。ランダムテストを準備しているあいだに次の問題を解いたほうが得点になることも多い。準備に 10 分以上かかりそうなら、その問題は飛ばす判断もする
- **愚直解も間違えうる**。食い違ったら、まず小さい入力を手で解いて、どちらが正しいかを確かめる
- 一致しても TLE やオーバーフローは見つからない（入力が小さいため）。計算量と、`int` で足りるかは別に確認する
- ビルドは `-D_GLIBCXX_DEBUG` 付きなので、`vector` の範囲外アクセスは RE として見つかる（ふだんのテストでは見つからないことがある）
- `contest/` は終了時点の状態を残す場所なので、`C.gen.py`・`C.brute.cpp`・`C.hack/` は終了後も消さずにそのままコミットする

### 終わったあと

1. インポート欄の先頭の **練習モードへ** を押して練習モードに戻す
2. 本番のコードを Claude で添削するときは、ランダムテストで見つかった入力（`C.hack/`）もノートに書いておくと振り返りやすい
3. 解けなかった問題を後から解くときは、**過去問を取得** で `practice/` に取り直す。ランダムテストを使うなら、上の「練習（過去問）での使い方」の手順でやり直す（`practice/` 側に `gen.py` / `brute.cpp` を作り直す）

## ターミナルから使う

```sh
# 雛形を作る（練習 / 本番）
./scripts/gen-init practice/ABC/485/C/main.cpp
./scripts/gen-init contest/ABC/485/C.cpp

# ランダムテスト（既定: 10 秒か 1000 件）
./scripts/stress practice/ABC/485/C/main.cpp
./scripts/stress --seconds 30 --max 5000 contest/ABC/485/C.cpp

# brute.cpp なし（RE / TLE だけ。WA は調べない）
./scripts/stress --no-brute practice/ABC/485/C/main.cpp

# gen.py の生成部分だけを確認する
./scripts/gen-init --print https://atcoder.jp/contests/abc485/tasks/abc485_c
```

## 設定

| 設定 | 既定 | 意味 |
| --- | --- | --- |
| `atcoder.stress.seconds` | 10 | **▶ ランダムテスト** / **▶ クラッシュ/TLE 検出** を続ける最大の秒数 |
| `atcoder.stress.maxCases` | 1000 | 試す最大の件数 |

## ビルドの違い

| | ▶ テスト実行（`scripts/test`） | ▶ ランダムテスト（`scripts/stress`） |
| --- | --- | --- |
| `-DLOCAL`（`dbg` が動く） | ✅ | ✅ |
| `-D_GLIBCXX_DEBUG`（`vector` の範囲外アクセスを検出） | ❌ | ✅ |
| AddressSanitizer / UBSan（配列外アクセス・符号付きオーバーフロー） | ❌ | Linux（devcontainer）のみ。macOS の GCC には無い |
| 自分の解が TLE とみなされる時間 | 2 秒（サイドバーから実行したとき） | 2 秒 |
