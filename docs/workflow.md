# 問題を解く流れ

基本は左端の **AC アイコン**を押して開くサイドバーで操作する。

```
ATCODER
├─ インポート … 種類と番号を選んで「過去問を取得」または「コンテスト用に作成」
├─ テスト     … 開いている main.cpp を「▶ テスト実行」、結果をサンプルごとに表示
└─ ノート     … 開いている問題の解法ノート（note.md）を status・タグを選んで作成、または開く
```

## コンテストの指定

インポート欄の **種類** をプルダウンで選び、必要なら番号や ID を入れる。実際に使われるコンテストIDは入力欄の下に `→ abc380` のように表示される。

| 種類 | 入力 | コンテストID | フォルダ |
| --- | --- | --- | --- |
| ABC / ARC / AGC / AHC | 番号（`380`、`42` は `042` に0埋め） | `abc380` | `ABC/380` |
| 典型90問 | なし | `typical90` | `TYPICAL90` |
| EDPC（DP まとめ） | なし | `dp` | `DP` |
| 鉄則本 | なし | `tessoku-book` | `TESSOKU-BOOK` |
| ABS | なし | `abs` | `ABS` |
| アルゴリズムと数学 | なし | `math-and-algorithm` | `MATH-AND-ALGORITHM` |
| その他 | ID 全体（URL の `contests/` の後ろ。例: `hhkb2020`） | そのまま | 大文字 1 階層（`HHKB2020`） |

「問題」欄には問題一覧の左端のラベルを入れる（大文字・小文字は区別しない）。

| 種類 | ラベルの例 |
| --- | --- |
| ABC など | `a` `b` … |
| 典型90問・アルゴリズムと数学 | `001` `002` … |
| 鉄則本 | `a01` … `c20` |
| ABS | `PracticeA` `ABC086A` … |

典型90問（90問）や鉄則本（151問）のように問題数が多いものは、空欄で全問を取得すると AtCoder に大量にアクセスすることになる。解く問題だけを指定する。短時間に何度も取得すると「アクセスが多すぎます（HTTP 429）」と出るので、1分ほど待ってから再実行する。

## ディレクトリの分け方

| ディレクトリ | 置くもの |
| --- | --- |
| `contest/` | 実際に参加したコンテスト。**コンテスト終了時点の状態**を残す（終了後は変更しない） |
| `practice/` | 過去問。参加した回で解けなかった問題を後から解く（upsolve）ときもこちら |

たとえば ABC484 に参加して A〜E を解いた場合、`contest/ABC/484/` には A〜E を残す。後日 F を解くときは、**過去問を取得** で `practice/ABC/484/F/` に取得して解く。

## コンテストに参加するとき

コンテスト開始前に、インポート欄で種類（ABC など）と番号を選んで **コンテスト用に作成** を押す。通信はせず、`base.cpp` をコピーしたファイルを問題ごとに作る（既存のファイルは上書きしない）。

```
contest/ABC/485/
├── A.cpp    ← 中身は base.cpp と同じ
├── B.cpp
├── ...
└── G.cpp
```

- 作る問題は決め打ち: ABC は A〜G、ARC・AGC は A〜F、AHC は A のみ
- 「問題」欄に `h` のように入れると、その問題だけ追加で作れる
- 対応しているのは ABC / ARC / AGC / AHC だけ
- サンプル（`test/`）は作らないので、サイドバーのテストは使えない。サンプルは問題ページで確認する

ターミナルなら `./scripts/new --contest abc485`（追加は `./scripts/new --contest abc485 h`）。

## 1サイクル（過去問）

### 1. 問題を取得する

**インポート** 欄で種類と番号を選び、**過去問を取得** を押すと `practice/` に作られる。特定の問題だけなら「問題」欄に `a c` のように入れる。

取得後は最初の問題の `main.cpp` が開く。一覧の問題名をクリックすると各問題を開ける。次のように作られる（既存の `main.cpp` は上書きしない）。

```
practice/ABC/380/
├── A/
│   ├── main.cpp      ← base.cpp のコピー。1行目に問題URL
│   └── test/         ← サンプルケース（git 管理外）
│       ├── sample-1.in
│       └── sample-1.out
└── B/ ...
```

### 2. 問題を読む

**テスト** 欄の **問題を開く** を押す（または `main.cpp` の1行目の URL を **Cmd + クリック**）。

### 3. 解く

`main.cpp` を編集する。保存時に自動でフォーマットされる。

### 4. サンプルでテストする

`main.cpp` を開いた状態で **テスト** 欄の **▶ テスト実行** を押す（未保存なら自動で保存される）。

- AtCoder と同じオプションでビルドし、`test/` のサンプルを 1 件ずつ実行する
- サンプルごとに **AC / WA / RE / TLE** と実行時間を表示する。AC 以外は「入力 / 期待する出力 / あなたの出力」が開いた状態で出る
- 2 秒を超えると TLE、6 秒で強制終了する
- コンパイルエラーはテスト欄にそのまま表示される

自分で考えたケースを試すときは、`test/` に `custom-1.in` と `custom-1.out` を置くと一緒にテストされる。

### 5. 提出する

**テスト** 欄の **コピーして提出ページへ** を押す。コードがクリップボードにコピーされ、ブラウザで提出ページが開く。貼り付けて、言語に **C++23 (GCC 15.2.0)** を選んで提出する。

### 6. ノートを書く

**ノート** 欄で作る。`note.md` がまだなければ、次の項目を選んだり入力したりして **📝 ノートを作成して開く** を押す。同じディレクトリに `note.md` が作られて開く。

| 項目 | 入れ方 |
| --- | --- |
| status | `本番AC` / `自力AC` / `解説AC` / `未AC` から選ぶ |
| tags | カンマ区切りで入力する。下に出る「候補」（他のノートで使ったタグ。よく使う順）を押すと追加される |
| 時間計算量（time） | `O(N log N)` のように入力する |
| 空間計算量（space） | `O(N)` のように入力する |
| 復習対象（review） | チェックすると `review: true` |

- どれも空のままでよい。作成後に `note.md` の frontmatter を直接書き換えられる
- フォームで指定できるのは作るときだけ。既に `note.md` があるときはフォームが出ず、**📝 ノートを開く** が出る（**📋 Claude の出力を取り込む** はどちらの場合も出る）
- tags と計算量には `#` `[` `]` `,` と「`: `」は使えない（YAML が壊れるため）

中身は `base-note.md` をコピーし、選んだ値を入れたもの。本文は見出しだけなので自分で書く。

```markdown
---
status:               # 本番AC / 自力AC / 解説AC / 未AC
tags: []              # 大分類と具体的な手法を両方（例: [DP, 桁DP]）
time:                 # 時間計算量 例: O(N log N)
space:                # 空間計算量 例: O(N)
review: false         # 復習対象なら true
---

## 着眼点
<!-- どの条件・制約から何に気づけば解法に辿り着けるか -->

## 解法
<!-- 手順と、なぜそれで正しいか -->

## ハマった点・学び
<!-- 次に同じ型が出たとき何を思い出せばよいか。WA/TLE の原因 -->

<!-- Claude の添削・解説を貼るときはこの下に「## Claude による添削・解説（AI生成）」の節を足す -->
```

- 問題URLは `main.cpp` の1行目、日付は git の履歴で分かるので書かない
- `contest/` の `E.cpp` などを開いて押した場合は、`contest/` には作らず `practice/ABC/484/E/note.md` に作る（`contest/` は終了時点の状態を残す場所のため）。`practice/` 側に `main.cpp` が無いときは、frontmatter に `url:` が入る
- `practice/` の古い形式（`practice/ABC/483/A.cpp` のように `A.cpp` を直接置く形式）ではノートを作れない

#### Claude で添削をもらう

本文を自分で書いた後、スキル `atcoder-review` で添削・解説をもらえる。返ってくるのは、判定・添削（修正は差分の提案まで）・解説・過去ノートとの照合と、tags / time / space / review の提案。

**VS Code から（Claude Code）**

前提: [Claude Code](https://code.claude.com/docs/en/overview) をインストールし、ターミナルで一度 `claude` を起動して `/login` しておく。

1. 添削したい `main.cpp`（`contest/` の `E.cpp` なども可）を開く
2. **ノート** 欄の **🤖 Claude で添削** を押す。裏で `claude -p` が起動し、欄に「問題文を取得中」「サンプルでテスト実行中」などの状況が出る（**キャンセル** で止められる）
   - `contest/` の解答では、起動前に「コンテストは終了していますか？」と確認される
   - `contest/` の解答の隣に `test/` が無ければ、`practice/` 側で取得したサンプル（`practice/ABC/484/E/test`）でテストする（テスト欄・`./scripts/test` も同じ）
3. 終わると、添削・解説のパネルと、今の `note.md` と適用後の差分が開く
4. 差分を確認して、パネルの **適用** を押すと `note.md` に取り込まれて開く。値が入っている tags なども Claude の提案で置き換えるなら **上書きして適用**

- Claude に許しているのは、ファイルの読み取り・`./scripts/test`・`./scripts/note --history` / `--info`・AtCoder のページの取得・Web 検索だけ。ファイルの編集と git は禁止しているので、`note.md` を書き換えるのは **適用** を押したときだけ
- `.claude/skills/atcoder-review/` のスキルを使う。ターミナルの `claude` で「`practice/ABC/380/A/main.cpp` を atcoder-review で添削して」と頼んでも同じ形式で返る
- 失敗したとき（`claude` が見つからない／未ログイン／タイムアウト／取り込み用ブロックが無い）は理由が通知に出る。**出力を表示** で Claude の生の出力を確認できる（出力パネルの「AtCoder: Claude」）

| 設定 | 既定 | 内容 |
| --- | --- | --- |
| `atcoder.claude.model` | `sonnet` | 使うモデル（`sonnet` / `opus`） |
| `atcoder.claude.timeoutSec` | `300` | これを超えたら止める（秒） |
| `atcoder.claude.path` | `claude` | `claude` が見つからないと言われたら絶対パス（`which claude` の結果）を指定する |

**claude.ai から**

1. claude.ai のスキル `atcoder-review` に、問題URLと `main.cpp` のパス（または中身）を渡す
2. 返ってきたコピペ用ブロック（`---` で始まる frontmatter と `## Claude による添削・解説（AI生成）` の節）をコピーする
3. 添削してもらったファイル（`main.cpp`、または `contest/` の `E.cpp` など）を開いた状態で、**ノート** 欄の **📋 Claude の出力を取り込む** を押す。`note.md` に取り込まれて開く

どちらの方法でも、取り込みでは次のように書き換わる（`note.md` が無ければ先に作る）。

- frontmatter は `tags` `time` `space` `review` だけ。**status は変えない**
- 今の値が空のキー（`review` は `false` も空とみなす）は Claude の値で埋める。値が入っているキーは変えずに通知で知らせ、**上書きする** を押したときだけ上書きする
- AI 生成の節は、本番（`contest/` の解答）と復習（`practice/` の `main.cpp`）で分けて持つ
  - 本番: `## Claude による添削・解説（AI生成・本番）`。`contest/` のファイルを開いて取り込んだときと、見出しが本番のときはこちら
  - 復習: `## Claude による添削・解説（AI生成）`
- 同じ見出しの節が既にあれば、その節（次の AI 生成の節の手前まで）だけを置き換える（何度取り込んでも同じ結果になる）。もう一方の節は残る。無ければ、本番の節は復習の節の手前に、復習の節は末尾に足す。AI 生成の節より上の本文は変えない
- 復習を何度しても、残る復習の節は最新の1つだけ（前の添削とコードは git の履歴で追う）
- 節の先頭には、添削したコードへのリンク（`対象: [contest/ABC/484/E.cpp](...)` など）が入る
- frontmatter か見出しが無い内容（関係ないものをコピーしていた場合など）はエラーになり、何も変えない

ターミナルなら `./scripts/note --apply practice/ABC/380/A`（クリップボードから読む）。ファイルからは `--from out.md`、標準入力からは `--from -`、値が入っているキーも上書きするなら `--overwrite` を付ける。`--dry-run` を付けると書き込まずに取り込み後の全文を出す。`./scripts/note --history` は全ノートの path / url / status / tags を JSON で出す（過去ノートとの照合に使う）。

**開催中のコンテスト（ABC / ARC / AGC）の問題には使わない**（[AtCoder生成AI対策ルール](https://info.atcoder.jp/entry/llm-rules-ja)）。過去問の練習と、コンテスト終了後の振り返りだけに使う。

### 7. コミットする

```sh
git add practice/ABC/380/A/main.cpp practice/ABC/380/A/note.md
git commit -m "feat:ABC380 A を解いた"
```

`test/` やビルド成果物（`*.out`）は `.gitignore` で除外している。

## 出力の比較方法

AtCoder の[コンテストルール](https://atcoder.jp/contests/abc380/rules)に合わせ、**空白と改行を区別せず、単語の列が一致すれば AC** とする。

> 本来の正しい出力について、空白文字（CR/LF/Space/Tab）を別の空白文字に置き換えたり、空白文字を先頭・末尾・別の空白文字の直後に追加したものを出力した場合も正解と判定されます。

- 末尾の改行が無い、行末に空白がある、などの違いは AC になる。完全一致ではないときは「（空白・改行の違いあり）」と注記が出る
- 問題文に「このルールは適用されない」と書かれた問題は例外なので、出力形式を正確に合わせる
- 下記の Test ボタン・`scripts/test` も同じ比較（`oj t -N`）にしている。oj の既定は完全一致なので、`oj t` を直接使うと末尾の改行が無いだけで WA になる

小数を出力する問題（「誤差 10^-6 まで許容」など）は、サイドバーでは誤差を考慮しないため、桁数の違いだけで WA になることがある。その場合は問題のディレクトリで次を実行する。

```sh
oj t -e 1e-6 -c ./main.out -d test
```

## サイドバー以外の操作方法

| 操作 | ステータスバー（最下部） | ターミナル |
| --- | --- | --- |
| 過去問を取得 | **New** ボタン | `./scripts/new abc380`（特定の問題だけなら `./scripts/new abc380 a c`） |
| コンテスト用に作成 | **New** ボタンで `--contest abc485` と入力 | `./scripts/new --contest abc485` |
| テスト | **Test** ボタン | `./scripts/test practice/ABC/380/A/main.cpp` |
| ノートを作る | **Note** ボタン（パスが表示されるので Cmd + クリックで開く。値は空で作る） | `./scripts/note practice/ABC/380/A`（`contest/ABC/484/E.cpp` も指定できる。値は `--status 自力AC --tags DP,二分探索 --time "O(N log N)" --space "O(N)" --review` で指定） |

コマンドパレット（**Cmd + Shift + P**）の **Tasks: Run Task** からも同じタスクを選べる。ほかに次のタスクがある。

| タスク | 内容 |
| --- | --- |
| **build**（Cmd + Shift + B） | ビルドだけ行う（`<ファイル名>.out` を生成） |
| **build & run** | ビルドして実行。入力はターミナルから打ち込む |

## 古い解答について

`contest/ABC/484`・`practice/ABC/483` は `scripts/new` を作る前の形式（`A.cpp` を直接置く形式）。`test/` が無いのでテストは使えない。`practice/ABC/483` はノートも作れない。build と[デバッグ](debug.md)はそのまま使える。
