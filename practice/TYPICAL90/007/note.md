### 添削
指摘なし。
- オーバーフロー: A と B は 1e9 以下なので差は 1e9 未満。`inf`（2^30-1 ≒ 1.07e9）より小さく、`int` で収まる。
- 計算量: ソート O(N log N)、クエリ O(Q log N)。N, Q ≤ 1e5 で十分間に合う。
- 補足: `test/hack-002.out` だけが残っているようなので、`.in` を補うか `.out` を消すと `scripts/test` が動く。
- 補足: `int q;` の宣言と読み込みが離れているので、`int q; cin >> q;` を A の読み込みの後にまとめると読みやすい。動作には影響しない。

### 解説
- **着眼点**: 各クエリは「A の中で t に最も近い値」を探す問題。A を一度ソートすれば、答えの候補は t の直前と直後の要素だけに絞れる。
- **想定解**: A をソートし、クエリごとに二分探索で t 以上の最初の要素を求める。その要素と1つ前の要素を比べて小さい方の差を出力する。計算量は O((N+Q) log N)。
- **本人の解法との比較**: 想定解と同じ。`lower_bound` の結果の前後を `inf` で番兵処理しているので、場合分けも少なく良い実装。
- 別解: クエリもソートして A と二つのポインタで走査すると O(N log N + Q log Q)。オフラインで処理でき、実装は二分探索の方が短い。
