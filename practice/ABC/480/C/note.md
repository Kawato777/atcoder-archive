### 添削
指摘は小さいものだけで、WA・TLE・オーバーフローになる入力は見つかりませんでした。

1. **`A[i] + k > l` は常に真で冗長**です。`l` は初期値 0 か直前の `A[i-1] + k` で、`A[i-1] < A[i]` なので `l < A[i] + k` が必ず成り立ちます（重複は `unique` 済み）。
2. **`l = A[i] + k;` が両分岐で共通**なので、外に出せます。

```diff
-        if (A[i] + k > l && l >= A[i]) {
-            l = A[i] + k;
-        } else {
-            result += (A[i] - l + k - 1) / k;
-            l = A[i] + k;
-        }
+        if (l < A[i]) result += (A[i] - l + k - 1) / k;
+        l = A[i] + k;
```

3. **`unique` は本問では不要**です。同じ値が続いても `l >= A[i]` 側で `l = A[i] + k` が同じ値になるだけで、答えは変わりません。害はないので残しても問題ありません。
4. **`A[i] + k` は int 同士の加算**です。最大 2×10^9 は int の上限 2147483647 に収まるので今回は安全ですが、余裕がありません。`vector<ll>` で受けると安心です。
5. `ceil` 部分は `A[i] - l > 0` と `t - l > 0` が事前に保証されているので `(x + y - 1) / y` で正しいです。

### 解説
- **着眼点**: 青木君のボタンはお湯の切れ目を伸ばすだけです。時刻 0 から T までを左から順に見て、お湯が出ている範囲の右端 `l` を持ちます。次の押下時刻 `A_i` が `l` 以前なら切れずに `A_i + K` まで延びます。`l` より後なら、`[l, A_i)` の隙間を高橋君が長さ K ずつ埋めます。
- **隙間の埋め方**: ちょうど K 秒後も出ているとみなされるので、`l` ちょうどに押せば途切れません。隙間の埋め方は `l, l+K, ...` と押す形で最小になり、回数は `ceil((A_i - l) / K)` です。最後に `[l, T]` も同じ式で埋めます。
- **想定解**: ソートして左から貪欲に 1 回走査します。O(N log N)（ソート済みなら O(N)）です。公式解説は参照していません。上の方針は問題文と愚直解との一致から確認したものです。
- **本人の解法との比較**: 方針は上と同じです。
- **別解（番兵版）**: `A_i` を `min(A_i, T)` に丸めて `T` も配列に入れると、`break` や末尾の特別処理が不要になります。同じ 3000 ケースで元の解答と一致しました。

```cpp
for (auto& x : A) x = min<ll>(x, t);
A.push_back(t);
sort(A.begin(), A.end());
ll res = 0, l = 0;
for (ll a : A) { if (l < a) res += (a - l + k - 1) / k; l = a + k; }
```
