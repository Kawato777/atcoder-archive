### 添削
- `E[i]`（区間末尾の1つ先までの距離）は、最後の区間では存在しない点を指す。それが `F[i] = min(F[i-1]+1, E[i])` に混入し、`F[i-1]` に右側の情報が混ざった状態で `+1` されて誤差が伝播する。
- 反例: `8 / 1 2 1 2 1 1 1 1` → 正解 `1 1 1 1 1 2 3 4`、part4 は `1 1 1 1 1 2 2 3`。
- 「解説あり」のコードは未完成（`d` を出力していない）。最後のループは次の形で完成する。

```diff
     for(int i=0;i<n;i++){
         int d=n;
-        if(L[i] !=0) d = min(d,i-L[i] +1);
+        if(L[i] != 0)   d = min(d, i - L[i] + 1);
```

### 解説
**着眼点**
- 答えは「左側で最も近い異色の点」と「右側で最も近い異色の点」の小さい方で、左右は独立に求められる。
- 存在しない側は INF にする。2種類以上の色があるので、どちらか一方は必ず存在する。

**想定解（O(N)）**
左から1回、右から1回スキャンして `min` を取る。

```cpp
const int INF = 1e9;
vector<int> L(n, INF), R(n, INF);
for (int i = 1; i < n; i++)
    L[i] = (C[i] == C[i-1]) ? (L[i-1] >= INF ? INF : L[i-1] + 1) : 1;
for (int i = n-2; i >= 0; i--)
    R[i] = (C[i] == C[i+1]) ? (R[i+1] >= INF ? INF : R[i+1] + 1) : 1;
// 答え: min(L[i], R[i])
```

**本人の解法との比較**
複雑になった原因は3つ。
1. 区間長を配列 D に圧縮して E に展開し直していた。隣と比べる漸化式があれば不要。
2. 左右の情報を1本の配列 F に混ぜていた。別配列にして最後に `min` を取れば、端の特別扱いが消える。
3. 「存在しない」を表す値がなく、境界ごとの場合分けが増えた。

設計の前に「左右に分解できるか」「存在しない側を INF で表せるか」を確認する。

別解: 解説の `L[i]`/`R[i]`（区間の始点・終点）を持つ方法。
