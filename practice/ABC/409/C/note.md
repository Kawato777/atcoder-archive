### 添削
指摘なし（WA や TLE になる入力は見つからなかった）。確認した点は次のとおり。
- L が 3 の倍数でないときは、問題を読む前に 0 を出力して終わる（62〜65 行目）。入力を読み残しても出力に影響しない。
- 座標を `d >= 1` と `d < L` の前提で更新している（74〜77 行目）。`p + d` は 2L 未満なので、1 回引くだけで範囲に収まる。
- 答えは最大で約 (10^5)^3 = 10^15 になる。`point` は `vector<ll>` なので、積も `long long` で計算される。オーバーフローしない。
- 座標が重なる点（周回して同じ位置に来る点）も `point[p]++` で数えている。

任意の整理として、次のように書くと分岐が 1 行になる。

```diff
-        if (p + d >= l)
-            p += d - l;
-        else
-            p += d;
+        p = (p + d) % l;
```

`endl` は最後の 1 回だけなので問題ない。

### 解説
- **着眼点**: 円周を 3 等分する 3 点は、座標が (x, x+L/3, x+2L/3) の形になる。同じ座標の点が複数あってもよいので、座標ごとの点の個数を数えれば足りる。
- **想定解**: 点 1 を原点にして、各点の円周上の座標を累積和（mod L）で求める。座標ごとの個数 `cnt` を作り、`0 <= x < L/3` の各 x について `cnt[x] * cnt[x+L/3] * cnt[x+2L/3]` を足す。L が 3 の倍数でなければ答えは 0。計算量は O(N + L)。
- **本人の解法との比較**: 想定解と同じ方針で、実装も無駄がない。x を `[0, L/3)` に限っているので、同じ三角形を重複して数えることもない。
- 別解: 座標をソートして `map` で数える方法もあるが、L が 3×10^5 以下なので配列のほうが簡潔で速い。
