### 判定
正しいと思います。問題文の3つのサンプルが一致し、愚直解（全窓を set で数える）とのランダム比較300ケース（N≤10, 値1〜4）も全て一致しました。N=3×10^5, K=150000, 値が全て異なる最大級の入力で0.35秒でした。

### 添削
指摘は小さなものだけで、WA・TLE・オーバーフローの心配はありません。

- 正当性: 窓が `[0,K)` から `[i+1, i+K]` へずれる更新で、先頭の削除と末尾の追加の順序も合っています。K=N のときはループが0回で、初期窓の `result` がそのまま答えになります。N=1 も問題ありません。
- 削除の書き方: 「引いて、0になったら消す」は1行にまとめられます。`q[C[i]]` を2回引く手間も減ります。
- `result` の更新は `max` で書けます。`q.size()` は `size_t` なので、現状の `result = q.size()` は暗黙の縮小変換になっています。

```cpp
-        if (q[C[i]] == 1)
-            q.erase(C[i]);
-        else
-            q[C[i]]--;
+        if (--q[C[i]] == 0) q.erase(C[i]);
         q[C[i + k]]++;
-        if (result < (int)q.size()) result = q.size();
+        result = max(result, (int)q.size());
```

`if (--q[C[i]] == 0) q.erase(C[i]);` の `q[C[i]]` は、必ず既存キーに対する操作です。窓に入っている値を引くので、存在しないキーが勝手に追加される心配はありません。

### 解説
- **着眼点**: 取る K 個は連続区間で、求めるのは「区間内の異なる値の個数」の最大値です。窓を1つずらすと入れ替わるのは両端の1要素ずつなので、毎回数え直さず差分更新できます。
- **想定解**: 長さ K の窓を右へずらしながら、値ごとの個数を持ちます。個数が0になった値は消し、種類数を更新して最大を取ります。窓を動かす回数は N 回で、各操作が O(log N) なので全体で O(N log N) です。
- **本人の解法との比較**: 想定解とほぼ同じです。個数が0になった値を `erase` しているため、`q.size()` がそのまま種類数になっています。この設計が一番きれいな点です。
- **別解**: 座標圧縮して `vector<int> cnt` を使うと、種類数を変数で持てて O(N log N)（ソートのみ）になり、`map` より定数が軽くなります。値が 10^9 まであるので、配列を直接添字にするにはこの圧縮が要ります。`unordered_map` でも通りますが、普通は `map` で十分です。

### 学んだこと
- [知恵袋: 配列内の値の出現数を数える](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q13230803713): `map<int,int>` でキーを値、数値を出現数にして、`count[v]++` の1行で集計できる、という内容です。コードでは `q[C[i + k]]++` と初期窓の `q[C[i]]++` がこれにあたります。
- [競プロ覚書：std::map の使い方 - pyてよn日記](https://pyteyon.hatenablog.com/entry/2019/02/22/200000): `mp[S]++` での加算、`find`・`lower_bound` などのイテレータ操作、内部が平衡二分木でキー順に並ぶこと、が書かれています。コードの `q[...]++` が該当します。ただし、`erase` とキー不在時の挙動はこの記事では扱われていませんでした。
- [std::mapまとめ - Qiita](https://qiita.com/_EnumHack/items/f462042ec99a31881a81): `operator[]` は存在しないキーを指定すると既定値の要素を追加すること、キー指定での削除ができること、検索が対数時間であること、が書かれています。コードでは `q.erase(C[i])` が削除、`q.size()` が「個数が0の値は消してある」前提の種類数にあたります。
