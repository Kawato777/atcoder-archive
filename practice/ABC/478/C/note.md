### 添削
**1. `minmax_element` の終端が1つ足りない（AC済みだが誤答になりうる）**

`l` は最初に下がる位置の添字で、`m` は最後に下がる位置の次の添字。整っていない部分は `A[l..m]` だが、`A.begin() + m` は `A[m]` を含まない。

反例は `N=4, K=3, A = 4 4 3 3`。

- 正解は `No`。ソート後は `3 3 4 4` なので、4要素すべてが位置違いで、窓が3では足りない。
- 提出コードは `A[m]=3` を見落とし、min=max=4 のまま左へ広げず、`Yes` を出す。

```diff
-    auto minmax = minmax_element(A.begin() + l, A.begin() + m);
+    auto minmax = minmax_element(A.begin() + l, A.begin() + m + 1);
```

**2. 左右に広げるときに min/max を更新しなくてよい理由**

- 左に足す要素は prefix の要素で、`A[l]` 以下かつ `min` より大きいので、min も max も変わらない。
- 右に足す要素も同様に、`A[m]` 以上かつ `max` より小さいので、min も max も変わらない。
- この性質に依存したコードなので、コメントを1行書いておくと後で読み返すときに助かる。

**3. その他（軽微）**
- `l == m` になるのは全体が昇順のときだけで、そのときは `l = n-1, m = 0` になる。`l > m` のガードで足りる。前回のREはこのガードで解消している。
- `.at()` は添字ミスの発見には便利だが、提出時は `[]` でも十分。
- 区間の端は、半開区間 `[l, r)` か閉区間 `[l, r]` かを最初にコメントで決めておくと、今回のようなミスを避けやすい。

### 解説
- **着眼点**: 窓をソートしても、窓の外は動かない。そのため、最終的にソート済みになるには「ソート後の配列 B と A が食い違う位置」がすべて窓に入る必要がある。食い違う位置の最小を `l`、最大を `r` とすると、条件は `r - l + 1 <= K`。窓は長さ K で、K < N なので、`[l, r]` を含む窓は必ず配置できる。
- **想定解**: `B = sorted(A)` を作り、先頭と末尾から A と B の食い違いを探す。`l` が存在しなければ `Yes`（すでに昇順）、存在すれば `r - l + 1 <= K` で判定する。計算量は O(N log N)。A_i ≤ N なので、計数ソートにすれば O(N)。
- **本人の解法との比較**:
  - 方針は「昇順でない部分を求め、そこに含めるべき要素を外側へ広げる」ことで、結局は同じ区間を求めている。計算量は O(N) で、ソートを使わない分だけ速い。
  - ただし、境界（`m` を含めるか）の管理が必要になり、今回そこにミスがあった。ソート済み配列との比較なら、境界の取り違えがほぼ起きない。
- **別解**:

```cpp
auto B = A; sort(B.begin(), B.end());
int l = 0;
while (l < n && A[l] == B[l]) l++;
if (l == n) { cout << "Yes\n"; return 0; }
int r = n - 1;
while (A[r] == B[r]) r--;
cout << (r - l + 1 <= k ? "Yes" : "No") << "\n";
```

### 学んだこと
- [C++ イテレータ（frkz.jp）](https://frkz.jp/study/cpp/iterator)
  - `end()` は最後の要素の次を指す印で、参照できない。`begin() + n` のような演算で位置を指せる。
  - このページには `minmax_element` の説明はない。
  - コードでは `A.begin() + l` や `A.begin() + m` がこの使い方で、`end` に相当する側（`+ m`）が「含まない」という点が、今回の境界ミスの原因。
- [vector・array・配列での最大値・最小値の取得（Qiita）](https://qiita.com/dsy_i07/items/9f8184bc46684d0eaca0)
  - `minmax_element` は先頭と末尾のイテレータを受け取り、最小と最大の位置を `pair` で返す。値を取るには `*` が必要。
  - コードでは `*minmax.first`（最小）と `*minmax.second`（最大）が対応する。
- [std::copy（cpprefjp）](https://cpprefjp.github.io/reference/algorithm/copy.html)
  - 範囲は半開区間 `[first, last)` で、`last` は含まない。要素数は `last - first`。
  - このコードでは `std::copy` は使っていない。ただし、標準アルゴリズムの範囲指定は共通して半開区間なので、`minmax_element(l, m)` が `A[m]` を含まない理由はこの規則（ページに `minmax_element` の記述はなく、一般則としての対応づけ）。
