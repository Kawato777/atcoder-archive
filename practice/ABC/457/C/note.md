### 添削
指摘は致命的なものなし。簡潔さと安全性の改善のみ。

1. `l == 0` の分岐は不要。`B[l-1]` を使うために場合分けが生まれている。累積和配列を持たず、K から塊の長さを引きながら進めると、`B`・`l`・分岐がすべて消える。
2. `(k - B[l - 1] - 1) % A[l].size()` は `ll % size_t` なので、左辺が `unsigned long` に変換される。今回は左辺が必ず 0 以上なので正しく動くが、負になりうる式だと壊れる。`ll` にキャストするか、`ll len = A[i].size()` と先に符号付きに揃えておくと安全。
3. 読み込みで `vector<int> b(l); cin >> b; a = b;` とすると、一時 vector へのコピーが1回余分に走る。`a.resize(l); cin >> a;` で足りる（動作は同じで、ΣL ≤ 2×10^5 なので速度差は出ない）。

### 解説
- **着眼点**: B そのものは最大 2×10^14 要素で、作れない。ただし B は「A_i を C_i 回繰り返した塊」を順に並べたものなので、K 番目がどの塊に入るかは塊の長さ（L_i × C_i）だけで決まる。塊が決まれば、中身は周期 L_i の繰り返しなので、塊内の位置から (位置 − 1) mod L_i で添字が出る。
- **想定解**: 塊の長さの累積和を取り、K を初めて超える塊を探して、その塊の中で mod を取る。時間 O(N + ΣL)、空間 O(ΣL)。
- **本人の解法との比較**: 方針は想定解と同じ。累積和 `B` を配列で持つか、K から引きながら進むかの違いで、計算量は変わらない。引きながら進む形の方が、場合分けが要らず、バグが入りにくい。
- **別解**: 累積和配列に対して `lower_bound` で塊を二分探索すれば O(N log N) になるが、N ≤ 2×10^5 なので線形走査で十分。
