### 添削
指摘は優先度の低い実装面のみです。正当性・オーバーフロー・計算量の問題はありません。

1. `map<int, vector<int>> D` は `vector` の中身（添字 `i`）を使っておらず、`.size()` しか見ていません。単なる個数カウントなので `map<int,int>` で足ります。
2. `D[a]` は参照のたびに要素を挿入します。`result` は変わりませんが、読むだけの場面なので意図が伝わりにくいです。
3. 値の範囲が 1..N なので、`vector<int>` の配列カウントなら `map` の log が消えて O(N) になります。

```diff
-    map<int, vector<int>> D;
-    for (int i = 0; i < n; i++) D[B[C[i] - 1]].push_back(i);
-    for (auto&& a : A) {
-        int i = (int)D[a].size();
-        if (i >= 1) result += i;
-    }
+    vector<int> cnt(n + 1);
+    for (int i = 0; i < n; i++) cnt[B[C[i] - 1]]++;
+    for (auto&& a : A) result += cnt[a];
```

`if (i >= 1)` は不要です。サイズは 0 以上なので、そのまま足して構いません。

### 解説
- **着眼点**: 条件は A_i = B[C_j] を満たす組 (i, j) の個数です。i と j は独立に選べるので、A の値ごとの個数と B[C_j] の値ごとの個数に分解できます。
- **想定解**: B[C_j] の値ごとの出現回数を数え、A の各要素について対応する回数を足します。配列カウントなら O(N)、`map` でも O(N log N) で、N が 10^5 規模なら十分間に合います。
- **本人の解法との比較**: 方針は想定解と同じです。違いはカウントに `map<int, vector<int>>` を使っている点だけで、`map<int,int>` か配列にすると簡潔になります。
- **別解**: A と B[C_j] の両方を値ごとにカウントして、積の総和を取っても同じです。
