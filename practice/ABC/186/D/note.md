### 判定
正しいと思う。サンプル2件が一致し、愚直解との500件のランダム比較（N=2〜8、値域 ±3/±100/±10^8）も全て一致。最大ケース（N=2×10^5、±10^8 を半々）は 0.07 秒、答えは 2×10^18 で `long long` に収まる。

### 添削
指摘なし。`A` と `B` が `ll` なので `A[i] * i` でオーバーフローしない。累積和を変数1つで持てば追加空間を O(1) にできるが、可読性は今の形のほうが良い。

### 解説
- **着眼点**: 答えは並び順に依存しないのでソートできる。ソート後は i < j で |A_i − A_j| = A_j − A_i と絶対値を外せ、j ごとの寄与は「A_j × j − 前の要素の和」になる。
- **想定解**: ソート O(N log N) と累積和による総和 O(N)。全体 O(N log N)、空間 O(N)。
- **本人の解法との比較**: 想定解の一つと同じ。コメントアウトの O(N²) 版は N=2×10^5 で約 2×10^10 回となり TLE する。
- **別解**: 各 A_i に係数 (2i − N + 1) を掛けて足す。A_i は後ろとの差で N−i−1 回加算され、前との差で i 回減算されるため。累積和を作らず O(N) で計算できる。

### 学んだこと
- [Qiita: 累積和（drken）](https://qiita.com/drken/items/56a6b68edef8fc605821): 前処理 O(N) で区間和を s[right] − s[left] の O(1) で求める手法。この解答では `B[i + 1] = B[i] + A[i]` が構築、`B[i]` が先頭 i 個の和にあたる。
- [drken's blog: ABC186 解説](https://drken1215.hatenablog.com/entry/2020/12/19/231000): ソートで絶対値を外して累積和で足す方針と、係数 (2i − N + 1) の別解。解答の `result += A[i] * i - B[i]` は前者そのもの。ページ本文は取得上限で途中までしか読めておらず、要約は取得できた範囲に基づく。
