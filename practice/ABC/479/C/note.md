### 判定
正しいと思う。問題のサンプル3つはすべて一致（12 / 0 / 21）。N=1〜8 のランダム300ケースを bit 全探索の愚直解と比較して、すべて一致した。N=20、A=10^9 の最大ケースは約 0.15 秒（制限 2 秒）。

### 添削
指摘は優先度の高い順に2点。どちらも正当性には影響しない。

1. **`Q` の保持とソートは不要（実装の簡略化）**
   - 各部分集合について「体積が W 以下ならおいしさの最大値を更新」すれば足りる。メモリは O(2^N) から O(1) になり、`sort` も要らない。
   - 今のコードも正しい。`(a, b)` を `greater{}` で降順に並べると、先頭から見て最初に `b <= w` を満たすものが `a` 最大になるため。ただし、全部分集合を保存して並べ替える分だけ回りくどい。

   +    ll ans = 0;
        for (int bit = 0; bit < (1 << n); ++bit) {

   - 空集合（bit=0）で `a=0, b=0` となり `b <= w` を満たす（W≥1）。「何も選ばない」ケースは `ans = 0` の初期値と合わせて自然に扱える。

2. **`endl` は `'\n'` で十分（軽微）**
   - 出力は1回だけなので実害はない。`cin.tie(nullptr)` などで高速化しているので、癖として `'\n'` に揃えておくとよい。

オーバーフロー: 合計は最大 20×10^9 = 2×10^10 で `int` には収まらない。`a, b` を `ll` にしているので問題なし。`p` は `int` だが、1要素は 10^9 以下なので入力は `int` で足りる。`1 << n`（n≤20）、`1 << i` も `int` で安全。

### 解説
- **着眼点**: N ≤ 20 なので、選ぶ・選ばないの全パターン 2^N ≈ 10^6 通りを調べ切れる。W、A、B がともに 10^9 まで大きいので、重さや価値を添字にする典型的な DP（ナップサック）は使えない。「制約が小さいのは N だけ」に気づくのが入口。
- **想定解**: 部分集合を全列挙し、体積の総和が W 以下のものの中でおいしさの総和の最大を取る。計算量 O(N 2^N)、これは約 2×10^7 回の操作。
- **本人の解法との比較**: 方針は想定解と同じ。違いは「全部保存してソートする」か「走査しながら最大を更新する」かだけ。後者の方が短くメモリも使わない。計算量は前者もほぼ同じで、TLE にはならない。
- **別解**: 再帰（DFS）で「i 番目を選ぶ/選ばない」を分岐しても同じ O(2^N)。N が 40 程度まで増えた場合は半分全列挙（meet in the middle）が必要になる。今回は不要。

### 学んだこと
- [Qiita（drken）: 6. bit 全探索](https://qiita.com/drken/items/7c6ff2aa4d8fce1c9361#6-bit-%E5%85%A8%E6%8E%A2%E7%B4%A2)
  - 整数 `bit` の各ビットを「要素を選ぶ/選ばない」に対応させ、0 から 2^N−1 まで回すと全部分集合を列挙できる、という手法。
  - 対応箇所: `for (int bit = 0; bit < (1 << n); ++bit)` と、`if (bit & (1 << i))` で選んだ要素の `a, b` を足す部分。記事の部分和の例と同じ形。
  - 計算量が O(N 2^N) になるのは、記事ではなく一般的な見積もり。
- [Qiita（redpeaks33）: pair の sort](https://qiita.com/redpeaks33/items/7e024a7a9d36b3959295)
  - `pair` の sort は第1要素の昇順、同じなら第2要素の昇順になる。降順にしたいときは符号を反転する方法が紹介されている。
  - 対応箇所: `sort(Q.begin(), Q.end(), greater{})`。`greater{}` を使えば、符号を反転しなくても `(a, b)` の両方が降順になる。
  - ただし今回は、上の添削1のとおり `chmax` で更新すれば sort 自体が要らない。
