### 添削
指摘は 1 点で、動作には影響しません。

- 13〜16 行目: 先頭要素を読んでから `a.erase(a.begin())` で消しています。`vector` の先頭削除は 1 回 O(N) なので、全体では O(N^2) になります。この制約なら問題ありませんが、降順ソート済みなので消さずに `a[i]` を読めば済みます。

```diff
     for (int i = 0; i < n; i++) {

-            alice += *a.begin();

-            bob += *a.begin();

+            bob += a[i];
     }
```

- 偶奇で足す先を分けるより、符号を切り替えて 1 つの変数にまとめる書き方もあります（任意）。

### 解説
- **着眼点**: 2 人とも自分の得点を最大にしたいので、毎回その時点で残っている最大のカードを取るのが最善です。
  - 取る順番は「大きい順」で固定されるので、シミュレーションする必要がなく、降順に並べて交互に割り当てれば済みます。
- **想定解**: 降順にソートし、偶数番目（0 始まり）を Alice、奇数番目を Bob の得点として足し、差を出力します。計算量は O(N log N) です。
- **本人の解法との比較**: 方針は想定解と同じです。違うのは、先頭を `erase` している点だけです。`a[i]` を直接読めば O(N log N) になります。
- 別解: 昇順ソートのまま末尾から数えても同じです。`greater<int>()` の代わりに `ranges::sort(a, greater{})` も使えます。
