### 添削

実装面では次の2点が改善できる（任意）。

- 5桁に固定した桁分解（11〜16行目）は N が増えると崩れる。桁和を求める処理をループで書くと制約が変わっても壊れない

```diff

-        if (a <= o && o <= b) c.push_back(m);
+        if (a <= o && o <= b) sum += m;
...
-    o=0;
```

（`sum` は `int sum = 0;` を先に宣言する。出力末尾の改行は無くても通ることが多いが、付けておくと安全）

### 解説
- **着眼点**: N が小さいので、1〜N を全部調べて各数の桁和を計算すれば足りる
- **想定解**: 1〜N を走査し、桁和が A 以上 B 以下の数を合計する。桁和は 10 で割った余りを足して 10 で割る操作の繰り返しで求める。計算量は O(N log N)（N が桁数に比例する分だけ log が付く）、追加メモリは O(1) にできる
- **本人の解法との比較**: 方針は同じ。桁を 5 桁に固定して分解している点だけ違うが、この制約では問題ない。想定解のループ版は桁数に依存しないので汎用的
- 別解: 桁和を `to_string` した各文字から求める方法もある。短く書けるが、この制約では速度差は気にならない
